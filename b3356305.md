# Unified Calendar Backend Starter

This is a starter backend for a multi-account calendar app that connects Google Calendar and Microsoft 365 / Outlook calendars, stores normalized calendars and events in PostgreSQL through Prisma, and exposes unified API endpoints.

## What this starter includes

- Express + TypeScript backend
- Prisma schema for users, connected accounts, calendars, and unified events
- Google OAuth start/callback flow
- Microsoft OAuth start/callback flow
- Calendar discovery sync for both providers
- Event sync for both providers
- Unified events endpoint for the frontend
- Mock authentication middleware using `x-user-id` for local development

## Quick start

1. Copy `.env.example` to `.env`
2. Fill in Google and Microsoft OAuth credentials
3. Start PostgreSQL
4. Run:

```bash
npm install
npx prisma generate
npx prisma migrate dev --name init
npm run dev
```

## Important notes

- Google push notifications are documented via Google Calendar push notification guides, and incremental sync should use sync tokens.[cite:39][cite:8]
- Microsoft Graph supports delta queries for tracking changed calendar resources and events, which is the recommended pattern for efficient incremental sync.[cite:45][cite:51]
- This starter keeps one sync cursor on the connected account for simplicity. In production, store cursors per calendar because Google sync tokens and Microsoft delta links are usually scoped to resource/query boundaries.[cite:8][cite:45][cite:51]
- Refresh-token rotation and automatic token refresh are not fully implemented in this starter and should be added before production use.
- Webhook subscription creation and renewal are not included yet.

## API endpoints

- `GET /health`
- `GET /api/oauth/google`
- `GET /api/oauth/google/callback`
- `GET /api/oauth/microsoft`
- `GET /api/oauth/microsoft/callback`
- `GET /api/accounts`
- `POST /api/accounts/:accountId/sync`
- `GET /api/calendar/events?start=...&end=...`
